TASK 1 • APPLICATION & GIT

Strict input boundaries; pure transaction rules

  • GET /health: liveness, not business correctness.
  • POST /validate: five required string fields; unknown fields rejected.
  • Decimal money; no float intermediates, coercion or silent rounding.
  • Positive amount, limit, currency, precision and distinct-account rules.

LESSONS • NEXT STEPS • EVALUATOR ACCESS

Keep provenance stronger than the success badge

Lessons from actual failures

  • Build #22: scanner panic, then Docker I/O errors. Approved recovery restored access—not proof of full volume integrity.
  • A loaded configuration can keep working while its file bind is unreadable. Check bytes and mounts, not email alone.
  • Persist actual checkout revision; an inline probe is not automatic SCM proof.
  • Retain failed reports and distinguish image archive, loaded image and deployment.

Remaining work

  • Agree provider/account eligibility, spending, exposure and teardown before cloud work.
